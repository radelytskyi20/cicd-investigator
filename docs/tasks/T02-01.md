## Stack

C#; EF Core; Microsoft.EntityFrameworkCore.SqlServer and Design; SQL Server in Docker; Aspire; xUnit.

## Goal

Create a coherent domain schema and repeatable data for the first investigation.

## Implementation

1. Create src/CiCdInvestigator.Data for EF logic genuinely shared by MCP and API. Place DbContext, entities and migrations there. Avoid additional empty Shared, Contracts, Domain and Repository projects.
2. Model Pipeline, Run, Job, optional Step, attempt identity, positioned LogEntry, Commit, available ChangeSet and TestResult. Include dataset version and source completeness/availability. Separate execution state from outcome.
3. Add the initial migration and one migration/seed owner. Proposed owner: MCP host before readiness; API must not race schema updates. The same owner applies later report migrations.
4. Seed a small S01: a successful baseline, a failed run, jobs, test results, logs and a causally relevant diff. Use stable identifiers and idempotent seeding without deleting saved reports.
5. Keep evaluator expectations in tests/fixtures or docs/evaluation, outside agent-visible data. Do not expose rootCause, expectedAnswer or scenario names that reveal the answer.

## Acceptance and checks

- A clean SQL Server database is created by migrations. Repeated seeding creates no duplicates and restart preserves data.
- Run/job/attempt/test/log relationships and baseline chronology are coherent. Relevant tests cover relationships, idempotence and missing versus complete data.
- Queries and constraints are checked against SQL Server, not only EF InMemory.
