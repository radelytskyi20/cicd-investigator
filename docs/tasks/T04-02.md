# T04-02 Build the run catalog and details UI

Stage 4 | Status: Planned | Depends on: [T04-01](T04-01.md)

Read repository [AGENTS.md](../../AGENTS.md), [decisions](../decisions.md), [requirements](../requirements.md) and the [task index](README.md).

## Stack

React; TypeScript; Vite; native fetch; plain CSS; REST API; Vitest and Testing Library for meaningful behavior only.

## Goal

Let the user choose a run and inspect its source data.

## Implementation

1. Add a simple catalog with pipeline/ref/outcome filters, time ordering and run links. Read REST data rather than duplicating mock fixtures in the frontend.
2. Show run context, jobs, simple steps/attempts, positioned log fragments, tests and commits/diffs. Mark source completeness.
3. Distinguish loading, empty and error states. Use English labels. Display the baseline and any comparability warning.
4. Add Investigate failure for completed failed runs and pass the exact run ID to the investigation page.
5. Use ordinary components and CSS. A small router is acceptable if needed for these pages; Redux and a design system are unnecessary.

## Acceptance and checks

- Filters and details use the backend and preserve run/attempt identity.
- Partial and unavailable logs differ; API errors are not empty catalogs. Type checking and production build pass.
- Check a useful selection path and an error state rather than testing every heading string.

## Exclusions

No accessibility project, complex grid, log editor or browser-side AI calls.
