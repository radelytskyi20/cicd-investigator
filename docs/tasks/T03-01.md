# T03-01 Validate Copilot SDK with the MCP server

Stage 3 | Status: In progress | Depends on: [T02-04](T02-04.md)

## Stack

C#; GitHub.Copilot.SDK for .NET; compatible Copilot CLI runtime; Streamable HTTP MCP; ASP.NET Core; xUnit for adapter mechanics.

## Goal

Validate SDK integration before implementing the main agent service.

## Implementation

1. Create a minimal experiment inside API using CopilotClient, one session and McpServers pointing at the Aspire-managed server. Use the agreed Copilot access rather than another model API.
2. Pin a compatible SDK/runtime pair. If the SDK offers a bundled runtime, select and document one runtime source instead of assuming compatibility with any installed CLI.
3. Confirm authentication, a real call to our MCP tool, tool lifecycle events, final response and reliable completion signal. Capture source results needed to validate evidence later.
4. Verify SDK cancellation, session disposal and termination of application-owned child processes. Returning from an awaited call does not by itself prove analysis stopped.
5. Reuse existing local authentication and create fresh conversations. CLI-managed files are acceptable. Do not implement custom storage isolation, transcript cleanup or credential management. Do not change global settings or delete unrelated sessions. Verify fresh-session behavior in T03-01-02.
6. Record working APIs, versions, events, cancellation and storage in docs/decisions.md or a linked focused decision note. Do not turn the spike into a permanent extra application.

## Acceptance and checks

- A real SDK session invokes our tool and uses its result; events identify the tool and investigation.
- Cancellation stops further MCP calls and releases owned resources without hidden continuation.
- Actual runtime storage behavior is documented. An incompatible SDK is a blocker; CLI-managed files are acceptable for this local prototype.

## Exclusions

No Process.Start wrapper or handwritten JSON-RPC instead of SDK, universal provider, UI or second agent loop. Do not silently replace the chosen SDK or constraints.
