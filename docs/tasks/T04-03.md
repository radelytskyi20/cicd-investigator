# T04-03 Build investigation chat and report history

Stage 4 | Status: Planned | Depends on: [T04-02](T04-02.md)

Read repository [AGENTS.md](../../AGENTS.md), [decisions](../decisions.md), [requirements](../requirements.md) and the [task index](README.md).

## Stack

React; TypeScript; @microsoft/signalr; REST fetch; Vite; plain CSS; existing hub and Report DTO.

## Goal

Connect the user to the agent and completed reports through a minimal interface.

## Implementation

1. Connect to T03-02 hub without automatic reconnect. Show target run, baseline, current action, actual tool calls, simple chat and Stop.
2. Render answerReady with outcome, category, confidence/reason, hypotheses, evidence and recommendations. Evidence opens the correct source through REST.
3. Send follow-ups in the same SDK session to demonstrate short-term memory. Do not restore chat from localStorage, SQL or a saved session ID after tab closure or refresh.
4. Offer Save report only for a checked completed result. Confirm saving only after backend success; on failure retain text in the open tab and allow retry.
5. Show a basic report list and revisions. A new analysis of a saved run starts a fresh session rather than resuming its old conversation.
6. Dispose the connection and session when leaving the investigation page. Server lifecycle handles tab closure independently of browser-only callbacks.

## Acceptance and checks

- Catalog, investigation, follow-up, evidence, Save and history use real APIs and SDK integration.
- History contains completed results, not unfinished chats. Fresh tabs do not inherit old session context.
- Model errors, Stop and Save failures show actual state. English labels and ordinary lists/forms are sufficient.

## Exclusions

No resume, background completion, export, persisted chat, elaborate animation, accessibility project or cause graph.
