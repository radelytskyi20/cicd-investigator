## What to build

One SignalR client starts an investigation, receives real SDK/tool events and an answer, asks follow-up questions in the same conversation, or starts the next investigation with fresh context after a response completes.

## Acceptance criteria

- [x] A minimal service connects SignalR to the existing SDK and read-only MCP tools.
- [x] One current investigation and one active request exist application-wide.
- [x] Follow-ups reuse conversation and tool results; a new investigation replaces the conversation.
- [x] Actual events report progress, tool activity, answers and errors; contracts are documented.
- [x] A real SignalR/SDK/MCP check verifies start, follow-up and a fresh investigation.
- [x] No multi-client management, parallel investigation queue, UI or report validation is added.
