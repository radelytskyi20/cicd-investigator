# T03-02 Implement connection-scoped agent sessions

Stage 3 | Status: Done | Depends on: [T03-01](T03-01.md)

Read repository [AGENTS.md](../../AGENTS.md), [decisions](../decisions.md), [requirements](../requirements.md) and the [task index](README.md).

## Stack

ASP.NET Core; C#; GitHub.Copilot.SDK; SignalR; CancellationToken; System.Text.Json; transient in-memory connection state.

## Goal

Keep one investigation and short-term memory alive only while its browser connection is open.

## Implementation

1. Implement InvestigationAgentService and a minimal SignalR hub. The application owns one SDK session for one client and runs one request at a time; follow-ups reuse that session, and a later Start replaces it with fresh context.
2. Client messages: start with run/goal/optional baseline, followUp and cancel. Server events: started, progress, toolStarted, toolCompleted, answer, error and ended. The answer is conversational; validated answerReady belongs to T03-03. Freeze semantics and DTOs in docs/api-contracts.md.
3. On disconnect, explicitly cancel SDK work and dispose session/transient state. Do not rely only on beforeunload. Disable automatic SignalR reconnect and Copilot session resume.
4. Stop cancels current generation; later work requires another user request in the still-open tab. Closing the tab destroys the session and does not delete previously saved reports.
5. Check normal closure, connection loss and host shutdown. Cancel only owned resources. Log technical errors without full transcripts or sensitive arguments.

## Acceptance and checks

- Two messages in the same session use prior messages and tool results; a fresh session does not inherit them.
- Once disconnect is detected, work stops without new calls, draft persistence or automatic recovery. Measure detection latency rather than promising instantaneous browser cancellation.
- Stop and shutdown leave no continuing analysis. Progress comes from actual events, not invented percentages.

## Exclusions

No persistent memory, resume, background queue, chat database or configurable work budgets. UI comes in stage 4.
