## What to build

An insufficient-data investigation yields a compact unknown-cause report. Invalid results yield an explicit error and permit a user-requested retry in the current conversation.

## Acceptance criteria

- [x] One minimal negative fixture is isolated in a test database; the complete scenario catalog stays in Stage 5.
- [x] A real SDK/MCP check reports symptoms, missing evidence and useful next checks without an invented cause.
- [x] Focused tests reject malformed reports, false citations, altered quotations and mixed identities/attempts.
- [x] Evidence can be reused within the current conversation, but not across new investigations.
- [x] Stop/disconnect do not publish interrupted reports as answerReady.
- [x] No automatic repair loop or transcript storage is introduced; actual checks and limits are documented.
