# T04-01 Expose read APIs and persist completed reports

Stage 4 | Status: Planned | Depends on: [T03-04](T03-04.md)

## Stack

ASP.NET Core Web API; EF Core SQL Server; CiCdInvestigator.Data; System.Text.Json; xUnit; ASP.NET Core test hosting.

## Goal

Provide frontend data and a minimal history of completed results.

## Implementation

1. Add REST endpoints for runs, jobs, logs, tests, commits and baselines using T02-02 services. These serve users; the agent still reads CI/CD facts through MCP.
2. Add Investigation and ReportRevision with minimal metadata and structured completed output. Evidence references and short quotations may live in report JSON, without a general event store or full log snapshots.
3. Add the migration to Data and apply it through the established single migration owner. MCP tools do not change the database.
4. Save only a validated completed result from an active session. The client sends its ready-result identifier, not arbitrary JSON assumed to be trustworthy.
5. A significant clarification of the same run/goal creates a revision; a new run or independent goal creates a new investigation. Repeated Save of one version is idempotent. Disconnect never auto-saves active state.
6. Document REST DTOs, endpoints and errors in English. Keep input DTOs separate from EF entities.

## Acceptance and checks

- Saved completed reports reopen after restart; transient states and messages are absent from SQL.
- Save does not duplicate a version or overwrite previous revisions. Invalid ready-result identifiers are rejected.
- Write failures do not return success. Old unavailable source versions are labelled rather than silently replaced.

## Exclusions

No restored chat, import/export, natural-language history search or separate memory store.
