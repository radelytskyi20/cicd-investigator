## Follow-up: terminal-launched Copilot failure

The owner reported the generic investigation error after starting from a terminal. API logs showed repeated Win32Exception failures while SQL/MCP stayed healthy. The original log contained no native code, so an exact Windows cause was not recoverable; executable resolution through the inherited PATH was the likely cause.

Start-Local now resolves an absolute Copilot executable path (with an explicit override and the existing Windows installation as fallback), and AppHost forwards it to API. Missing files fail before startup. API now distinguishes native process-launch errors and logs their numeric code without transcripts.

Checks: Release solution build passed with zero warnings/errors; an invalid explicit path was rejected before Aspire started. With the Copilot directory deliberately removed from the launching process PATH, the complete stack started and a real browser run-102 investigation returned a validated report in 30.3 seconds with 8 MCP tool calls. No authentication or global environment settings changed. This correction remains Ready for review.
