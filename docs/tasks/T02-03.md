## Stack

C#; ASP.NET Core; official MCP C# SDK and ModelContextProtocol.AspNetCore; Streamable HTTP; CiCdInvestigator.Data query services.

## Goal

Expose real read-only CI/CD tools over MCP.

## Implementation

1. Add the MCP endpoint /mcp to the existing host. Streamable HTTP is proposed so Aspire owns the process and clients connect to its address. Do not spawn another server over stdio.
2. Start with list_runs, get_run, get_jobs, read_job_log, get_test_results, get_changes and find_baselines. Combining tools is acceptable if required semantics and data access remain available; document the final catalog.
3. Describe purpose, parameters, object identity, completeness and errors for each tool. Return source data through T02-02 services rather than a precomputed diagnosis.
4. Expose only domain reads: no SQL executor, shell, mock updates, rerun, Git operations or report-saving tool.
5. Keep health and protocol endpoints distinct. Provide the actual MCP address to the API through Aspire.

## Acceptance and checks

- A protocol client discovers the catalog and invokes each tool on S01. Ordinary HTTP GET checks are insufficient.
- Unknown IDs, bad ranges and unavailable sources have distinguishable responses without crashing the host.
- Aspire restart retains one MCP server and no write tools are advertised.
